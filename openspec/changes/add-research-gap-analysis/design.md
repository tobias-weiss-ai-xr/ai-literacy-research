# Design — Add Research Gap Analysis

## Context

The corpus has 20 categories × 8 subcategories = 160 taxonomy cells. The
generated README already lists the "thinnest" cells (fewest papers), but
thinness alone is a weak signal: a cell with 2 papers that is also flat (no
recent growth) is less promising than a cell with 5 papers that is surging.

The momentum data already exists in `statistics.json` (12-month output
density and year-over-year growth per category). What is missing is a tool
that **joins** thinness with momentum to produce a ranked opportunity score.

## Goals / Non-Goals

**Goals:**
- A single tool `tools/research_gap_analyzer.py` that reads `statistics.json`
  and `papers.yaml`, computes a gap score per cell, and writes
  `docs/research/gap_analysis.md`.
- The gap score combines absolute count, thinness (count vs category average),
  and momentum (recent growth), so thin-and-surging cells rank highest.
- The tool is config-driven (reads `config/taxonomy.yaml` for display names)
  and deterministic (byte-identical output for unchanged inputs).
- Wired into the pipeline and CI so the report stays fresh.

**Non-Goals:**
- Not auto-discovering papers for thin cells.
- Not changing the taxonomy.
- Not generating briefs or articles (that is `brief_generator.py`'s job).

## Design Decisions

### Gap score formula

```
gap_score(cell) =
    thinness_weight * (1 - cell_count / category_avg_count)      # thinner = higher
  + momentum_weight * normalized_12m_growth(cell)                 # surging = higher
  + floor_bonus if cell_count <= gap_floor                        # very thin = bonus
```

Defaults (overridable via CLI flags):
- `--thinness-weight 0.6` — thinness dominates (we want white space)
- `--momentum-weight 0.4` — momentum is the opportunity amplifier
- `--gap-floor 5` — cells with ≤5 papers get a small floor bonus

The score is normalized to 0–100 in the report for readability.

### Output format

`docs/research/gap_analysis.md` contains:
1. A summary table: top 20 gap cells (cell, count, category avg, 12m growth, gap score).
2. One section per top cell: the cell, its count, the representative papers
   (up to 5, newest first), and a one-line "why this is a gap" note.
3. A footer: "Generated by `tools/research_gap_analyzer.py` — do not edit by hand."

### Pipeline position

```
validate_papers.py → generate_readme.py → standard_stats.py
  → research_gap_analyzer.py   ← NEW (consumes statistics.json)
  → generate_reports.py → visualize_statistics.py
```

Running after `standard_stats.py` is required because the analyzer reads
`statistics.json`. Running before `generate_reports.py` lets the reports
optionally cross-link to the gap analysis.

### Read-only contract

`docs/research/gap_analysis.md` is a generated artifact, like the other
reports. `AGENTS.md` and `openspec/specs/analysis-reporting/spec.md` already
forbid hand-editing generated files; this change extends that contract to the
new artifact.

## Risks

| Risk | Mitigation |
|------|------------|
| Gap score rewards noise (a cell with 1 paper and 1 recent paper looks "surging") | The momentum term uses 12-month count, not single-month; floor bonus is small |
| Report drifts from README's "thinnest cells" | The README's static list stays; the gap report is a richer companion, not a replacement |
| Agents hand-edit the report | Read-only contract + CI check (regenerate and diff) |

## Open Questions

1. Weight tuning (0.6/0.4) — start with defaults, revisit after first run.
2. Whether to embed the top-5 gap table into README.md directly or keep it
   only in `docs/research/gap_analysis.md` (proposal: keep separate, link from README).
